# 数据来源与真伪标注

**每一条数据都标明来源。请不要把示意数据当作真实统计对外陈述。**

五类标注（统一登记在 `src/data/provenance.ts`，界面右上「数据来源与口径」面板读取同一份登记表）：

- `REAL` — 有外部来源，附原文链接，可自行核对（知乎快照、平台归档聚合、公开复盘）
- `SELF` — 由用户自己填写/产生（档案、任务、胜利、自评）
- `CURATED` — 工程规则整理，不是外部样本（方向、前置条件、资源规则、环境原型）
- `APPROX` — 按常识填写的近似示意值（城市属性、坐标；资源存量只按档位展示）
- `HEURISTIC` — 启发式模型，尚未校准（阶段判定、相似度、稳定度）

### 界面中的标注

- 主要数字/结论旁有 `REAL / SELF / CURATED / APPROX / HEURISTIC` 小标签，悬停可看口径；
- 全部来源与边界集中在顶部「数据来源与口径」面板，避免分散在各页；
- 近似值不用于对外陈述，模型参数未校准；界面不再保留虚构示例复盘。

### 按图表看依据（新增）

顶部「数据来源与口径」面板新增「按图表看依据」页签，逐条登记界面上的图表 / 数字：

- **有依据**：可核对，或来自你的真实记录 / 行为；
- **部分依据**：有出处，但为近似值、工程规则、自评映射，或样本不足；
- **无外部依据**：规则假设 / 未校准模型，不能当事实对外陈述。

登记表在 `src/data/evidence-audit.ts`，与界面共用同一份数据。当前标记为「无外部依据」的部分：

| 图表 / 数字 | 为什么没有外部依据 | 怎么补 |
|---|---|---|
| 归属相似度 / 稳定度 | 权重与阈值未用外部样本校准 | 真实样本 + 专家标注后校准 |
| 长期记忆接近度 | 复用同一套未校准相似度 | 随相似度一起校准 |
| 沙盘预设动作的七维效果 | 写死的规则假设，无样本均值 | 记录真实动作与结果后校准 |
| 沙盘现金缓冲 / 精力余量 | 固定系数推导，不是金额 | **第 1 步直接采集现金可撑月数、每周可投入小时** |
| 沙盘「维持现状」对照 | 固定假设，没有真实“不行动”轨迹 | 未行动用户回访数据 |
| 沙盘落点 / 七维变化 | 规则累加 + 未校准相似度 | 与相似度模型一起校准 |
| 新用户初始档案 | 模板值，不是用户数据 | 已在沙盘提示“未完成第 1 步时显示初始值” |

「部分依据」中可以直接在第 1 步补数据的：七维处境、一次性资源窗口、执行清单预算。
建议补充的可核对事实：**可动用现金能撑几个月、每周可投入小时、需赡养/抚养人数、行业招聘景气**。
这些字段需要新增档案列与工作流入参后才能持久化到平台，当前尚未接入，先做审计与提示。

## 3. 同阶段去向（REAL 聚合）

第 2 步「同阶段」标签的百分比来自平台胜利档案的跨用户匿名聚合（工作流 `archive_choice_stats`）：按 `stage` 统计归档时的 `choice` 计数，同阶段满 5 条才显示占比；低于阈值只显示条数。

- 统计的是**归档时的决定**，不是日常行为；
- 同一用户多次归档会多次计入；
- 旧归档未记录 `stage` 的不计入；
- 不再使用演示分布；接口失败时显示重试，不回落编造数据。

## 6. 鉴权环境的坑

进程环境里存在 `ZHIHU_ACCESS_SECRET`，由桌面客户端注入：

- 不在用户级环境变量（HKCU Environment）
- 不在系统级环境变量（HKLM Environment）
- **在当前进程环境**，长度 92（base64，解码后 68 字节二进制）
- 进程链：`explorer.exe` → `raccoon-zhihu.exe` → `box-agent-acp.exe` → `bash.exe`

CLI 优先级是「环境变量 > 系统密钥库」。该注入值本身在线校验有效，
但与密钥库中的那把不同。**要用密钥库里的密钥必须先 `unset ZHIHU_ACCESS_SECRET`**。

注：Skill 文档声称"Officev3 会从本地 Agent 子进程环境中移除 ZHIHU_ACCESS_SECRET"，
但实测该变量确实存在于子进程环境中。这是客户端实现与文档不一致。
